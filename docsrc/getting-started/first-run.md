# First run

After [install](install.md), walk through a low-risk path: pick a tenant, confirm you are in the right one, then preview before anything Live runs.

## Checklist

1. **Launch** YeetnGreet on your PC
2. **Sign in** to the tenant you manage. Admin consent must already be granted in that tenant. See [Admin permissions and consent](permissions.md)
3. Confirm the tenant name / domain matches the request or ticket
4. Open **Offboard** or **Onboard** and use **Preview** (or equivalent review step) before confirm
5. Optionally save a **template** for your standard checklist

!!! tip "Managing several tenants?"
    If you look after more than one tenant (for example a parent company and its subsidiaries), read the tenant name before you confirm. YeetnGreet keeps work on the PC you are looking at, so the tenant switcher is your source of truth. See [Multi-tenant](../tenants/multi-tenant.md).

## Suggested first job

| Goal | Path |
| --- | --- |
| Practice offboard flow | [Offboard](../jobs/offboard.md) with a test user or dry-run style preview |
| Practice onboard flow | [Onboard](../jobs/onboard.md) creating a clearly labeled test account |
| See license value | [License audit](../reports/license-audit.md) on a tenant you know well |

## Where local files live

Working files (templates, local logs, and related data) stay on your device — typically under AppData or Documents — unless you choose another location. They are **not** uploaded to YeetnGreet’s cloud as job payloads.
