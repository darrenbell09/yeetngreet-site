# First run

After [install](install.md), walk through a low-risk path: pick a tenant, confirm you are in the right customer, then preview before anything Live runs.

## Checklist

1. **Launch** YeetnGreet on the technician PC
2. **Sign in** to the customer tenant you manage
3. Confirm the tenant name / domain matches the ticket
4. Open **Offboard** or **Onboard** and use **Preview** (or equivalent review step) before confirm
5. Optionally save a **template** if this customer has a standard checklist

!!! tip "MSP habit"
    Say the customer name out loud before you confirm. Multi-tenant switch mistakes are expensive — YeetnGreet keeps work on the PC you are looking at, so the UI tenant switcher is your source of truth. See [Multi-tenant](../tenants/multi-tenant.md).

## Suggested first job

| Goal | Path |
| --- | --- |
| Practice offboard flow | [Offboard](../jobs/offboard.md) with a test user or dry-run style preview |
| Practice onboard flow | [Onboard](../jobs/onboard.md) creating a clearly labeled test account |
| See license value | [License audit](../reports/license-audit.md) on a tenant you know well |

## Where local files live

Working files (templates, local logs, and related data) stay on the technician device — typically under AppData or Documents — unless you choose another location. They are **not** uploaded to YeetnGreet’s cloud as job payloads.
