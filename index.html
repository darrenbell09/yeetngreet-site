Where user lifecycle goes wrong

When every technician improvises, the same three problems show up in every Microsoft 365 tenant.

01

Offboarding skips company policy

A busy tech blocks sign-in and moves on. Sessions stay live, the mailbox isn’t converted or handed off, groups and roles stay put, and nobody can say which steps actually ran.

02

Onboarding misses user properties

New accounts land without a manager, department, job title, or usage location. Groups and licenses depend on who made the account that day.

03

Licenses stay on inactive users

Disabled accounts keep their licenses, prepaid licenses sit unassigned, and nobody checks which licensed users have stopped sending, receiving, or reading mail in the last 90 days.

Admin control

Admins set the policy. Technicians run it.

Admins create the onboarding and offboarding templates. Technicians apply them to a job and fill in who it’s for. They can’t change the steps, so nobody makes up policy on the fly.

Onboarding

Same onboarding, every time.

Pick the template, then fill in the user. Required fields are enforced before the job can run, and the template sets the groups and licenses.

  • Apply an Admin-made template
  • Required fields enforced: display name, UPN, and usage location, plus any the Admin adds, like manager
  • Groups and licenses come from the template, not memory

Offboarding templates

Technicians can’t change the steps.

On a Technician’s screen, company templates are review-only. The offboard actions are locked to what the Admin decided, from blocking sign-in to removing licenses last.

  • Locked for Technicians: review and apply only
  • Every leaver gets the same checklist
  • Admins create, edit, and set the default per tenant

Offboarding

Offboard with a checklist.

Select one leaver or many, apply the template, preview the plan, then type CONFIRM to run it, or schedule it for later.

  • Select users and apply a template
  • Preview every action before anything changes
  • Type CONFIRM, then run
